Front-end

Jornada do shopper — Troca

Mesma entrada da devolução, mas ao escolher Troca o shopper seleciona a nova variante do mesmo produto e, em seguida, reentra no fluxo de devolução para retornar o item original.

A seleção da variante de troca e a checagem de estoque (REQ-05) são internas — provavelmente OMS (a definir quem implementa), fora do protocolo de provider externo. Os SKUs ofertados são variantes do mesmo produto comprado, ao mesmo preço do item devolvido; uma variante fica disponível quando há estoque > 0 em qualquer warehouse/seller (disponibilidade agregada/global, ex.: via GET Inventory by SKU).

selected return method, method type (pickup / drop-off), selected drop-off location or pickup address, return code, tracking code, carrier / provider information, provider reference, shopper instructions, latest logistics status, logistics status history, timestamps (creation + status updates)

Resolução de troca (interna · fora do protocolo de provider)

A oferta de variantes de troca e a checagem de estoque não passam pelo provider externo. É uma resolução interna da plataforma (provavelmente OMS, a definir), consultando o inventário da VTEX.

Show possible exchange items OMS REQ-05
Acionado na tela T4 · Escolha o novo item (jornada de Troca) · não usa o protocolo de provider
1 → Catalog · identificar variantes
GET /api/catalog_system/pub/products/variations/{productId} → SKU variants of the same product (same price as the returned item)
2 → Inventory · checar estoque por variante
para cada SKU variante, request de estoque (a resposta já retorna o estoque de cada variante) → variante elegível quando stock > 0
A avaliar: quem implementa (suspeita: OMS) · qual rota de Inventory por variante · se o envio da nova variante gera novo pedido (escopo OMS).
