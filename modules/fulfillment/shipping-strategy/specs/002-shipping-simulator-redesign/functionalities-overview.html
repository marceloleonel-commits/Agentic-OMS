Shipping Simulator — Shoreline Redesign

New Functionalities · Priority Order · Product Brief review — Jun 2, 2026

Current Simulator: What to Keep, Review & Remove

Status What Notes
✓ Keep Core flow: input form → simulation results Same mental model, new UI
✓ Keep Result fields: carrier name, SLA tag, shipping price, lead time, quantity Already well understood by operators
✓ Keep Expanded detail: dock, warehouse, postal code range, weight range, absolute value, per-gram surcharge, % surcharge, dock→warehouse cost, scheduled delivery flag, time costs Carry forward as-is; may reorganize layout
✓ Keep Carrier rejection motive Already shown today — goal is to improve specificity, not remove
⚠ Review Cubic weight factor, max order value, cubic weight Confirm with eng whether actionable for operators or can be simplified/hidden
⚠ Review Time cost breakdown (dock / warehouse / transport shown separately) May consolidate into a single readable line, e.g., "5 days transport + 0 dock handling"
✕ Remove Manual country input Replaced by auto-resolution from the selected sales channel
✕ Remove SKU search with indistinguishable variant names Replaced by new picker showing SKU ID, variant name, EAN, reference code

New Functionalities — Priority Order

Priority Functionality Today New
P0 Seller-level simulation Simulation always runs against the main account — no way to scope to a specific seller Operators can select a seller and simulate within its logistics configuration
P0 Usage metrics No instrumentation — no visibility into how the tool is used by VTEX accounts Pre-migration baseline via legacy API logs (POST /api/logistics/pvt/shipping/calculate), then post-launch tracking per account: unique users, usage frequency, sales channel, seller, result count, errors — enabling before/after comparison
P1 Logistics route visibility Expanded detail shows dock and warehouse, but not which shipping policy is applied — root-cause diagnosis is incomplete Each result shows the full route: warehouse → dock → shipping policy
P1 Clear SKU variant identification All variants of the same product appear with identical names in the search dropdown — operator cannot tell which SKU they are simulating Search dropdown shows differentiating attributes per variant: SKU ID, variant name, EAN, reference code
P1 Carrier rejection reasons Rejection motive already shown (e.g., "dismissed due to priority"), but generic — operator cannot identify the root configuration issue Review and improve rejection reasons: out of postal code range, above weight limit, outside business hours, dimensions exceeded, etc.
P2 Recent simulations history Every session starts blank — no memory of previous simulations Last 5 simulations saved and restorable with one click (30-day TTL, per user) — covered in spec 002
P2 Delivery date display Results show lead time in days only (e.g., "3 dias") — no calendar date shown Results display the estimated delivery date (e.g., "Arrives June 5"), computed from lead time, business days, and cutoff hours
P3 Delivery vs. pickup separation Results mix delivery and pickup options without clear distinction Separate tabs or sections for delivery and pickup; each clearly labeled
P3 Correct local currency Always shows the platform default currency, ignoring the sales channel's configured currency (KI 514551) Currency auto-resolved from the selected sales channel
