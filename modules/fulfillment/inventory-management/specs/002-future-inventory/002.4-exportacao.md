# Future Inventory — Filtered Export (Prototype)

> **Area**: Navigable prototype of the **Inventário futuro** module — export action
> for the list already filtered on screen.
>
> **Prototype**:
> [`inventario-futuro-listagem.html`](./prototype/inventario-futuro-listagem.html) — the same
> single-file HTML used by the lot, SKU and creation flows.

## 1. Purpose

The listing needs an export action similar to the OMS pattern: the merchant filters the
screen until it represents the operational slice they care about, then exports that
same slice to a CSV file for offline analysis, reconciliation or sharing.

This is a list-level action. It does not create or mutate future inventory lots.

## 2. User Stories

### US-1: Export the current filtered result

- **Story**: As an operator, I want to export the current filtered result, so that I
  can work with the same set of lots or SKUs outside the Admin.
- **Acceptance Criteria**:
  - **Given** the listing has results, **when** I open the page header actions menu and
    choose **Exportar inventário futuro**, **then** a CSV file is downloaded and the
    menu closes.
  - **Given** search or filters are applied, **when** I export, **then** the CSV
    contains the full filtered result, not only the current page.
  - **Given** I am in the **Por lote** view, **when** I export, **then** each CSV row
    represents one lot.
  - **Given** I am in the **Por SKU** view, **when** I export, **then** each CSV row
    represents one `(lote, SKU)` pair.
  - **Given** no row matches the current search or filters, **when** I open the actions
    menu, **then** the export item is disabled.

## 3. Functional Requirements

- **FR-1**: Export lives in the page header actions menu — the Shoreline `Menu` with
  `type="actions"` and `iconOnly`, next to **Criar lote futuro** — as the item
  **Exportar inventário futuro**, carrying `IconArrowLineDown`. It is the second of
  three items: **Importar lotes via planilha** comes before it and, after a
  `MenuSeparator`, **Histórico de alterações** closes the menu. Those two have no
  screen yet and only dismiss the menu. Unavailability is expressed by the component's
  `data-disabled`, not by the element's `disabled`, so the item stays reachable by
  keyboard and announces itself as disabled.
- **FR-2**: Export uses the same query pipeline as the table: search, destination,
  arrival date, quantity and status filters.
- **FR-3**: Export ignores pagination. If the table says `1 — 25 de 231`, the export
  still contains all 231 filtered rows when no filter is applied.
- **FR-4**: The **Por lote** CSV columns are: `Lote ID`, `Nome do lote`, `Seller`,
  `Estoque`, `Quantidade`, `Reservas`, `Chegada`, `Status`.
- **FR-5**: The **Por SKU** CSV columns are: `SKU ID`, `Produto`, `Lote ID`,
  `Nome do lote`, `Seller`, `Estoque`, `Quantidade`, `Reservas`, `Chegada`, `Status`.
- **FR-6**: The downloaded filename identifies the view and date, using
  `inventario-futuro-por-lote-YYYY-MM-DD.csv` or
  `inventario-futuro-por-sku-YYYY-MM-DD.csv`.

## 4. Out of Scope

- Server-side export jobs.
- Email delivery, scheduled exports or async processing.
- XLSX generation.
- Exporting columns that are not visible in the selected view.

## 5. Prototype Notes

The prototype implements export client-side with `Blob` and a temporary download link.
This is sufficient to validate placement, copy and interaction. A production
implementation may need a backend job if filtered results exceed the Admin's practical
client-side limits.
